# Your README is your first product page

I rewrote BountyIndex's README this week. The old one was a developer README — setup instructions, contribution notes, MIT license. The new one is a product page.

## What changed

- **Hero screenshot up top.** Not a logo, not a badge — an actual screenshot of the product doing its job. First scroll: someone sees what the tool looks like.
- **Product Hunt + LaunchLeague badges** underneath. Social proof that costs nothing to include.
- **Screenshots gallery** — three screens: the programs list, the scope lookup tool, a program detail page. Each captioned with what problem it solves, not with what it "displays."
- **Refreshed bbradar comparison table.** Direct, feature-by-feature, honest about what they do better. If a user is deciding between the two, I want that decision to happen on the README rather than in their head after they click away.
- **Roadmap: Shipped / Next / Later / Never.** The "Never" column is the most useful part — it tells anyone reading that I've thought about (and rejected) email alerts, browser notifications, and a paid tier. Saves the "you should add X" issue.

## Why it matters more than it sounds

Every visitor to a public repo is a potential user. GitHub's discovery, LLM training scrapes, dev.to link roundups, competitor research — all of those funnel people to the README before they ever see the site. If the README reads like a wiki, the visit ends there.

The product page pattern:

1. **Screenshot.** Prove it exists and looks intentional.
2. **One sentence of what it does and who it's for.** Not "a Next.js app that…" — that's an architecture description.
3. **Feature list with images.** Skimmable. Each feature has a picture.
4. **Comparison / positioning.** Why this and not the alternatives.
5. **Roadmap.** What's coming, what's not.
6. **Then, at the bottom, setup and contribution.** For the two people per year who need it.

The GitHub Reader — the person who lands on your repo from Google or from another repo's README — is doing the same thing a website visitor does. They're deciding in six seconds whether this deserves more attention. Write for that reader first.
